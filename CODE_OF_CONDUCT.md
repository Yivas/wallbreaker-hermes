# Code of Conduct

## Our standard

Wallbreaker Hermes welcomes technical disagreement and careful security research. Participants must
communicate respectfully, stay on topic and protect information that could harm another person or
system if disclosed.

Expected behavior includes:

- criticizing ideas, code and evidence rather than people;
- giving enough context for others to reproduce or review a claim;
- respecting authorization, privacy, licenses and coordinated disclosure;
- accepting moderation decisions and correcting mistakes without retaliation.

Unacceptable behavior includes:

- harassment, threats, discriminatory language or unwanted sexual attention;
- publishing personal data, credentials, private prompts, exploit details or confidential reports;
- encouraging unauthorized access or using project channels to coordinate real-world harm;
- spam, impersonation, sustained disruption or retaliation against reporters and contributors.

## Scope

This code applies to issues, pull requests, reviews, discussions, commits and other project spaces.
It also applies when someone publicly represents the project or its community.

## Enforcement

Maintainers may edit or hide content, lock a conversation, reject or close a contribution, limit
participation or block an account. They will consider context, severity, repetition and the safety
of affected people when choosing a response.

Report visible violations with GitHub's reporting controls on the relevant content. For content
that should be handled confidentially, use GitHub's **Report content** flow so GitHub can review it
without requiring publication in a project issue. Do not use a public issue to disclose personal or
sensitive information.

Private Vulnerability Reporting is reserved for security vulnerabilities in Wallbreaker Hermes.
